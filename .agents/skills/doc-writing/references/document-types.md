# 专项文档要求

## Stage 文档

Stage 文档除记录进度外，还必须支持后续开发者接手，至少包括：

- 当前阶段目标。
- 当前 session 边界。
- 已完成步骤及每步影响范围。
- 当前未完成事项。
- 下一步最合理的起点。
- 客户硬约束与当前实现策略的区别。

Stage 文档不能只是任务清单，还应解释当前阶段为什么这样推进。

## Bug 文档

证据不足以精确定位问题时，不得把猜测写成结论。应记录：

- 复现条件。
- 观察到的现象。
- 已确认事实。
- 尚未确认的推测。
- 下一步定位动作。
- 优先执行该定位动作的原因。

必须明确区分证据和推测，避免误导后续修复方向。
