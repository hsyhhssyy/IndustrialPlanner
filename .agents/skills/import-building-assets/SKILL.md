# 网站建筑素材导入

美术交付源固定为 <https://hsyhhssyy.github.io/Endfield-Building-TopView-Assets/>。导入由本技能组织执行；不再接受 ZIP、PNG 大图拆分或按中文文件名猜设备的旧导入流程。

## 执行方式

按下面的 checklist 逐阶段执行。允许执行者核对字段、统计数量、比较哈希、按明确条件选择分支、运行已有命令和处理有限重试；不要求每个判断都请示用户。遇到需要新算法、协议解释、实体映射设计或跨模块改造的情况，停止相关批次，按“失败报告”交代缺口，不在导入途中开发解决。

首次网站接入与日常导入是两类工作。开始前先读 [项目接入与发布的就绪检查](references/project-import.md#执行前就绪检查)；其中尚未完成的能力不能通过增加提示词或勾选清单补足。本技能的维护不自动执行该维护清单中的代码改造。

接到素材导入任务后，先向用户给出本次七个阶段的进度 checklist；每完成一个阶段更新一次。`[x]` 只表示已有命令结果或产物证据，尚未执行和失败项保持 `[ ]`。不适用项写明来源依据，例如所选实体没有动画声明；“尚未实现”不属于不适用。只阅读当前阶段引用的章节；就绪检查失败时，无需继续研究其余协议。不要反复复制整份技术文档。

## 执行边界

- 用户要求导入、同步或更新素材才执行。已有明确范围就直接推进，不重复申请同一授权；创建、修改或校验本技能不构成导入授权。
- 只处理用户指定的建筑、变体或素材类别；未限定范围的“导入网站素材”按项目已有映射覆盖的全部素材处理，网站新增且没有项目映射的内容列为未映射项。当前正式入口仅支持完整已有映射；用户指定局部范围时按就绪检查报告不支持，不能扩大为全量或手工合并。
- 网站是美术数据来源，不能据此新增设备、改变配方或推断逻辑端口。网站 ID、Registry entityId 和 spriteId 必须分别对账；业务变更遵循项目模块规范。
- 每次导入必须一次完成两层产物：`resources/` 保留原尺寸、原始下载字节；`public/` 从同一批原件生成全部配置比例的发布版本。只更新其中一层、漏发某个比例或混用不同来源，都不算完成。
- 发布比例唯一配置为 `src/scripts/building-asset-publish-config.mjs` 的 `BUILDING_ASSET_PUBLISH_RESOLUTIONS`。导入前读取该常量及 `resolveBuildingAssetPublishTargets`；不得在技能、导入处理程序或运行时另外维护固定的缩放数值，也不得因为用户要求导入就自行改变该配置。
- 应用使用本项目发布后的本地资源。不得把运行时纹理 URL 改为美术网站，也不得执行下载的预览 JavaScript。

## 导入 checklist

### 1. 确定范围与检查执行条件

输入：用户要求、当前工作区、比例配置。完成证据：明确的导入范围、全部发布目标和已验证的执行入口。

- [ ] 区分“导入素材”与“核查网站 / 维护技能 / 重发本地素材”；后三种请求不进入下面的导入阶段。
- [ ] 记录用户指定的实体、变体、类别。范围未限定时选已有项目映射；中文设备名按项目 i18n 规则核对，不自行翻译成 ID。
- [ ] 查看当前工作区的 `git status --short`，记录已有改动；不读取其他分支或 worktree，不执行 Git 文件操作。
- [ ] 运行下方只读命令，列出全部 `resolution / outputDirectory`，确认 `resources` 原版不属于缩放列表。
- [ ] 核对本次范围涉及的 [就绪检查](references/project-import.md#执行前就绪检查)：网站输入、所需素材类别、全部比例、来源记录和整批应用均已有经过验证的入口。缺任何一项，在此停止，不先下载整批图片，不临时编写替代导入器。

在项目根目录执行，此命令只打印配置：

```bash
node --input-type=module -e 'import { resolveBuildingAssetPublishTargets } from "./src/scripts/building-asset-publish-config.mjs"; console.log(JSON.stringify(resolveBuildingAssetPublishTargets("public/3d-top-view"), null, 2));'
```

### 2. 固定网站发布

输入：阶段 1 的范围与执行入口。完成证据：本次发布编号、索引摘要及校验结果。

- [ ] 建立唯一暂存目录 `.temp/.trash/building-assets-import-<唯一批次>/`，记录实际路径。所有下载和派生文件先写入此处。
- [ ] 按 [网站来源与校验](references/site-source.md#一次发布的完整性链) 获取锚点、根索引和清单，先校验字节再消费元数据。
- [ ] 核对 `releaseId / sourceVersion`、schema、路径和分级索引一致性；记录根索引 SHA-256。
- [ ] 执行下方下载命令。它同时完成阶段 2 的固定发布和阶段 3 的下载校验；只运行一次。记录实际发布编号、索引摘要和 `source-receipt.json`，不用历史编号代替当前版本。

后续所有 `<批次目录>` 必须替换为同一个实际路径：

```bash
python3 src/scripts/building-assets-site-source.py --batch "<批次目录>"
```

### 3. 对账并下载原件

输入：已固定索引、`resources/building-top-view-v15.json` 及 Registry。完成证据：映射对账表和通过校验的原件清单。

- [ ] 按已有 `entityId / spriteId / sourcePath` 对照网站 ID 与视图，列出新增、变化、不变、缺失及未映射项。
- [ ] 按下方决策表处理未映射与缺失项，不新增 Registry 实体，不猜别名或变体。
- [ ] 使用已验证的依赖解析与下载入口取得本次范围的 JSON/WebP 闭包；逐文件确认大小、SHA-256 和原始来源路径，原件只保留一份。
- [ ] 核对下载器已完成结束锚点复查；发布不同会报错，不能混用新旧发布。

### 4. 生成全部发布版本

输入：通过校验的原件及阶段 1 的比例列表。完成证据：覆盖所有目标的产物矩阵与生成日志。

- [ ] 列出“实体 / 类别 / 比例 / 原件路径 / 产物路径”矩阵。核对静态图、静态遮罩、动画首帧、分页、动画遮罩、物流材质、高度特效；不适用类别必须有依据。
- [ ] 用 `resolveBuildingAssetPublishTargets` 解析本次暂存发布根目录，确认首项和额外版本目录互不覆盖。
- [ ] 按已验证的调用方式显式传入输入目录、所选 ID、每个目标的比例与输出目录；逐个完成列表，不用默认 CLI 重发旧来源。
- [ ] 每个版本直接从原件生成；按 [项目接入契约](references/project-import.md) 使用已实现的变换和采样，不修改逻辑占地、动画时序或缩放策略。
- [ ] 任一类别或比例生成失败，停止本批次。不得先应用成功部分，也不得用原尺寸产物填补失败版本。

按顺序执行；每条成功后勾选对应类别，失败则停止：

```bash
python3 src/scripts/building-assets-site-source.py --batch "<批次目录>" --metadata-only
node src/scripts/import-building-assets.mjs publish-static "<批次目录>"
node src/scripts/import-building-assets.mjs publish-animations "<批次目录>"
node src/scripts/import-building-assets.mjs publish-logistics "<批次目录>"
node src/scripts/import-building-assets.mjs publish-effects "<批次目录>"
```

这些入口自行遍历比例常量；执行者不要把列表改成单个硬编码比例。也可以用 `publish` 一次生成全部类别并验收，但不要两套命令重复运行。

### 5. 验收暂存产物

输入：阶段 4 的矩阵与产物。完成证据：每项验收结果和完整来源关联。

- [ ] 原件字节与固定索引一致；每个发布产物都能关联原件哈希、发布编号和实际比例。
- [ ] 矩阵无缺项，实际图片尺寸与目标比例一致；同版颜色图与遮罩尺寸一致，缩放后的宽高都是正整数；裁切特效按已实现的透明补边规则验收。
- [ ] 动画逻辑画布、阶段、页数、帧数和逐帧时长符合来源及发布协议；manifest 引用均存在。
- [ ] 对本次涉及的物流、高度和端口特效运行现有专项校验，确认状态映射、数值编码、坐标和依赖完整。
- [ ] 任一验收失败时保留错误证据，正式 `resources` 和 `public` 不写入。不能以脚本退出码为 0 代替产物验收。

运行统一验收；成功输出原件数、产物数和应用文件数，并生成 `application-plan.json`：

```bash
node src/scripts/import-building-assets.mjs validate "<批次目录>"
```

### 6. 整批应用

输入：全部验收通过的同一批原版与发布版本。完成证据：受影响文件清单、恢复副本和应用后的对账结果。

- [ ] 列出本次实际写入文件，核对与开始时已有改动是否重叠。发现不能按既有规则保留的用户改动时停止并报告具体文件；普通脏工作区不构成整批停止理由。
- [ ] 通过已验证的应用入口保存受影响文件的恢复副本，确认恢复仅针对本次实际写入范围。
- [ ] 在既有导入授权内一次应用 `resources` 原版和全部 `public` 版本，并复核来源、数量及引用。网站移除项单独报告，不据此直接删除项目资产。
- [ ] 应用失败时由恢复流程回到应用前状态；恢复失败须明确报告残留文件与副本路径，不继续覆盖，也不执行 Git 恢复命令。

所有前置项完成后，在既有导入授权内执行：

```bash
node src/scripts/import-building-assets.mjs apply "<批次目录>"
```

`apply` 会保存 `backup/` 和 `apply-journal.json`；发生写入错误时自动恢复。中断后先看 journal；确需恢复时执行 `restore "<批次目录>"`。不要删除失败批次或绕过 Registry 差异检查。

### 7. 检查与报告

输入：应用结果、检查日志。完成证据：最终状态、完成的 checklist 和验证结果。

- [ ] 按 `simple-check` 执行基础检查；用户已指定检查范围时遵循其范围。检查失败不擅自改断言或业务代码。
- [ ] 涉及应用内素材效果时，按 `playwright-cli` 和项目要求逐个验证三个 Screen Profile、保留截图并逐次清理；不自动运行正式 E2E 或 Blueprint。
- [ ] 报告发布编号、索引摘要、导入范围、原版数量、每个比例的目录和数量、未映射项及检查结果。区分“未应用”“应用失败已恢复”“已应用但检查未通过”和“导入完成”。
- [ ] 将本轮需要保留的报告和失败证据放在 `.temp/building-assets-import/<批次>/`；检查、截图证据留在各自规定目录，再清理本轮下载暂存和一次性脚本。若恢复失败，恢复副本不清理，报告其路径。

## 简单判断与停止条件

只按已列出的条件决定下一步；没有匹配规则的协议或数据差异，归入“停止并报告”，不推导新业务规则。

| 观察到的情况 | 执行动作 |
| --- | --- |
| 已有映射、契约不变，来源哈希发生变化 | 按正常流程生成并验收；哈希变化本身不是错误 |
| 来源哈希未变 | 核对现有全部版本是否齐全且来源、比例一致；由现有增量规则决定跳过或重建，不只看原件 |
| 网站新增内容没有项目映射，且用户未点名该内容 | 列入未映射清单，继续本次已有映射范围 |
| 用户点名的内容没有映射，或已有映射所需文件缺失 | 停止本批次，报告 ID、路径及缺项；不静默缩小范围 |
| 已确认物流契约的 `stateMapping` 为 `null` | 按“无不透明遮挡”处理，不合成高度图 |
| 单次超时、连接中断、HTTP 429 或 5xx | 同一文件、同一固定发布最多重试 2 次；不能重试成功则停止。429 遵循 `Retry-After`，未提供时等待 5 秒；长等待分段并报告进度 |
| 其他 HTTP 失败或重试用尽 | 停止，报告状态码与路径；不切换源站、凭据或旧包 |
| 哈希或大小不符、发布切换、未知 schema、无合法路径 | 停止本批次，记录实际值与期望值；不以重试绕过验证，不回退旧来源 |
| 元数据与 Registry 冲突，或需要新坐标/动画/采样规则 | 停止并提交维护问题；不重新居中、不猜旋转、不合成阶段、不修改业务接口 |
| 发布器缺少本次所需能力，或没有验证过的调用方式 | 停在就绪检查；不在导入中实现缺失接口，不用旧 ZIP、空文件或临时兼容层补齐 |

## 失败报告

- [ ] 标明停在第几阶段、哪一项；后续阶段保留为未执行。
- [ ] 给出实体 ID / 文件路径、预期值、实际值及日志位置；缺能力时给出具体函数或入口，不只写“需要更强模型”。
- [ ] 明确正式目录是否写入、是否恢复成功、恢复副本是否保留。
- [ ] 说明下一步所需的具体维护工作或缺失信息；不反复请求同一导入授权，不自动委派其他 Agent。
