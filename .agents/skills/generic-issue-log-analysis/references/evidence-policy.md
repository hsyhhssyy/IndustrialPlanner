# 公开 Issue 证据规则

## 数据边界

公开 issue 分析禁止引用或依赖以下私有数据：

- `.temp/json-export.json` 游戏客户端解包数据。
- `.docs/` 子模块中的设计文档和 stage 计划。

只能基于公开仓库代码、issue 正文和评论、公开附件、截图、用户提供的控制台输出、蓝图 JSON 或配置信息建立结论。涉及数据准确性但公开证据不足时，必须报告证据不足；不得转而使用私有解包数据补齐公开结论。

## 证据优先级

### 截图

截图是可视化工具最直接的现场证据，适合确认：

- 设备图标、连接线、端口位置等渲染状态。
- 面板数值和数据展示。
- 弹窗、遮罩、加载态。
- 布局、缩放和分辨率问题。

描述与截图冲突时，先解释冲突，再判断更可信的证据，不得忽略差异。

### Issue 正文和评论

用于提取操作路径、预期行为、复现步骤、版本、浏览器、设备以及相关设备或配方名称。

### 浏览器控制台

用于确认 JavaScript 错误堆栈、React 警告和数据解析异常。

### 蓝图 JSON 和配置附件

用于确认蓝图数据、导入导出和配置是否损坏。

## 仿真与游戏行为不一致

如果用户声称工具仿真与游戏行为不同，例如配方产物、耗时、端口或设备逻辑不一致，必须要求提供游戏内截图作为对照。没有游戏截图时只能标记为证据不足，不得给出最终根因结论。

获得对照后，逐项比较游戏截图与公开仿真数据或逻辑，并列出差异。

## 结论强度

- 不得仅凭 issue 文本下结论，必须回溯公开代码。
- 截图和分析冲突时必须先解释冲突。
- 证据缺少截图、复现步骤或控制台错误时，应明确缺失内容，并把判断标为初步结论。
- 必须区分表象、直接原因和系统根因。
