# 公开 Issue 分析流程

IndustrialPlanner 是运行在浏览器中的纯前端工厂规划工具，技术栈为 React、TypeScript 和 Vite。主要目录：

- `src/app/`：应用层 UI、面板、工具栏和状态管理。
- `src/editor/`：放置、验证、文档存储和视口等编辑器核心。
- `src/domain/`：设备、配方、蓝图等领域模型。
- `src/registry/`：配方、设备变体、物品等静态定义。
- `src/shared/i18n/`：多语言文案。
- `src/renderer/`：设备精灵和画布渲染。
- `src/simulation/`：仿真引擎。
- `blueprints/`：示例蓝图。
- `help/`：公开帮助文档。

## 1. 规范化输入

- 默认把 `#1234` 视为当前仓库 issue。
- 用户提供完整 issue URL 时，以该 URL 为准。
- 只分析可直接访问的公开 issue、评论、截图和附件。

## 2. 获取现场

读取 issue 正文和全部相关评论，提取：

- 版本、浏览器、设备类型。
- 预期行为和实际行为。
- 完整复现步骤。
- 截图、控制台错误、导出蓝图 JSON 或配置附件。

维护者或评论已有结论时仍需用公开代码和现场证据验证，不能直接照抄。

## 3. 建立复现路径

从文本和附件确定用户操作路径及问题发生时刻，再对照组件、状态流转和事件处理链路。截图重点观察 UI 是否正常渲染、异常遮罩或弹窗、数据展示和布局状态。

## 4. 回溯代码

先锁定关键组件，再沿真实数据流下钻。常用优先级：

1. `src/registry/`：静态数据定义。
2. `src/domain/`：领域模型和业务规则。
3. `src/editor/`：编辑器核心逻辑。
4. `src/simulation/`：仿真引擎。
5. `src/app/`：UI 层。
6. `src/shared/i18n/`：翻译文案。
7. `help/`：公开帮助文档。

涉及设备、物品、配方或界面中文名称时，先在 `src/shared/i18n/` 查询对应 id 和正式中文文案。找不到时输出 key/id，并说明未找到对应中文；用户自定义名称优先保留。

常见路径：

- 数据值错误：优先检查 `src/registry/`。
- 特定设备或分辨率异常：检查 `src/shared/browser/` 的环境判断。
- UI 表象：继续确认根因是否位于 registry、domain、editor、simulation 或 app 状态层。
- 不支持场景：用代码中的限制逻辑举证，不能只给主观判断。

## 5. 区分历史环境和当前分支

从 issue 文本还原报告时的版本与环境，对照当前代码判断问题仍存在还是可能已经修复。不得直接把当前分支视为 issue 当时的真实实现。

如果旧 issue 必须通过历史 tag、其他 branch 或 worktree 才能复核，停止当前回溯并向用户申请单独授权；未经授权不得读取。

## 6. 输出结论

明确区分：

- 已证实根因。
- 高概率怀疑点。
- 证据不足的待确认项。
- 当前主线是否可能已经修复。
- 可执行修复建议、需要补充的测试或验证、临时绕过方式。

代码证据使用远端 GitHub blob 行号链接：

```text
https://github.com/<owner>/<repo>/blob/<commit>/<path>#L14-L20
```

默认 `<commit>` 使用当前 `HEAD`。回答只保留关键代码片段，不倾倒整段源码。
